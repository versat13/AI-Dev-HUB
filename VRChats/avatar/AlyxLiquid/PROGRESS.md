# AlyxLiquid(VRChatアバター用 Alyx風ウォッカ瓶)進捗メモ

> **このプロジェクトは中止中(2026-10時点)。以下は古い情報。**
> テスト用アバターとして、改変公開が許可された無料Humanoidアバターを使用している(固有名は伏せている)。

更新: 2026-10-03 / Unity 2022.3.22f1, VRCSDK 3.10.5, MA 1.18.7, Built-in RP, プロジェクト GimmickAI_1(AAO も導入済みだがアバターには未使用)
要点だけ知りたいときは同じフォルダの `HANDOFF.md` を参照

## 方針
- 液面挙動(水平・体積保存・スロッシュ・高次モード・表面波・壁リング・メニスカス・細波・泡/白濁)を独自シェーダー、動きの状態は PhysBone 振り子に分担
- 液体: `AlyxLiquid/Liquid`(独自) / ガラス: lilToon 屈折(`Hidden/lilToonRefraction`, AlyxGlass_lilToon.mat) / Poiyomi は無料版のみのため不採用
- アセット: `Assets/AlyxLiquid/`(AlyxBottle.fbx, AlyxLiquid.shader, VolumeLUT/Profile.exr, AlyxBottle_Gimbal.prefab, AlyxLiquid_Vodka_Gimbal.mat, AlyxLiquid_RedWine_Gimbal.mat ほか)
- 優先順位(ユーザー指示): 水面の動きのリアリティ(過度に重くしない)。SSS など重い表現は使わず、泡で白っぽく見せる方向。泡はベタ塗りでなく細かい粒で(ベタ塗りは「汚い誤魔化し」と不評)
- 気泡はバグが多いとの評価で無効化(_BubbleAmount=0)。壁際に溜まる泡は可。小細工は逆効果になりやすい → ベンチで計測しながら効果の大きい順に直す
- 改訂した進め方(承認済み): 1 ベンチ(済) → 2 揺れの較正(前半済)とチラつき対策 → 3 映り込み・光(反射プローブ代替・ライトプローブ・下からの全反射) → 4 厚み・屈折を部分的に → 毎回負荷計測
  - 瓶全体の描画を一から作り替える案は取りやめ(効果の割にリスク大、優先の「動き」に効かない)
- Alyx の資料: 液体は瓶表面に描いた見た目だけで中身はない。本物の流体計算ではなくシェーダー。作者は実物の瓶を観察し動きと光への反応を研究(UploadVR, Road to VR)
- ユーザー評価(VR 実機): 大枠・波の速度・液面の感じ(表面波追加後)は良い

## 描画順(重要)
- 液体のキューは 2899(Transparent-101)。lilToon 屈折ガラスは 2900 で深度を書き込み、名前付き GrabPass を使う
- 液体がガラスより後だと、外から見たときガラスの深度に隠れて液体が消える(VR 実機で発生 → 修正済み)。必ず液体を先に描く

## スケール補正(2026-10-03 修正)
- 症状: VRChat でアバターの大きさを変えると瓶は追従するが液面は元の大きさのまま
- 原因: SkinnedMeshRenderer の unity_ObjectToWorld のスケールがアバターの拡大縮小に追従しない(固定のまま)。元の実装は uv1 × この行列で液体位置を作っていた
  - さらに元の実装では瓶の 0.8 倍が行列に入っておらず、液体が約 1.2 倍大きかった(ガラスに隠れて気付きにくかった)
- 修正: 振り子ボーンで運ぶ法線の長さ = 0.5 × 現在の実スケール(GPU スキニングは法線を正規化しない)を利用
  - g_sr = 2|normal| / 行列の列長。頂点位置(uv1 × g_sr)、ComputePlane/ComputeSlosh のスケール、フラグメントの物体座標変換(÷ g_sr)を補正
  - v2f.scaleR(TEXCOORD8)でフラグメントへ渡し、静的グローバル g_sr に設定
- 検証: Play でルートを 0.5/1/1.5/2 倍 → 全て液面が瓶に一致。VR 実機での確認待ち(法線が正規化される環境だと 2 倍になる前提リスク)

## 比較用ベンチ(2026-10-03 作成)
- `Assets/AlyxLiquid/Dev/AlyxBench.cs` + `AlyxLiquid_Bench.unity`(開発専用、アバターに載せない)。Play で自動実行(Bench オブジェクトの runTag で出力先を切り替え)
- Hand(握り位置)を動かす 4 動作: shake(左右 2Hz・4cm を 2 秒)/ tiltstop(0.4 秒で 60° 傾けて停止)/ flick(0.3 秒で 5cm 一往復)/ swirl(半径 3cm・1.5Hz で 3 周)
- Time.captureFramerate=60 で決定的に進め 15fps で記録。横(6°)と斜め上(40°)の 2 視点を 1 タイル(320px)、1 動作 = 1 枚の一覧画像(6 列×10 行)+ 振り子角度の CSV(t, fastDeg, slowDeg)
- 出力: `AlyxDebug/bench/<runTag>/`(baseline, tip025_050, tip025_100, calib1)
- 撮影前に空撮り 3 回(新規マテリアルが水色になるのを防ぐ)
- 1 回の実行は Play 開始から約 100 秒(MCP の再接続待ち込み)

## ベースライン計測(2026-10-03)と物理の見積もり
- 一次モード: R≈2.66cm(0.8 倍), k=1.841/R → 約 4.1Hz。減衰比 1〜2% と見積もり → 約 2.5 秒で 1/e
- 見積もり: swirl 定常 約 17°(遠心加速度 2.66m/s² → 15° × 共振増幅 1.15)、shake 約 43°(33° × 1.31)

| runTag | swirl 定常(速/遅) | shake 1〜2 秒の最大(速) | 遅い振り子の最大(shake / flick) |
|---|---|---|---|
| baseline(tip 0.01 / 0.02) | 35° / 73° | 72° | 178° / 174°(反転) |
| tip025_050 | 16° / 61° | 40° | 73° / 63° |
| tip025_100(採用) | 16° / 57° | 40° | 49° / 44° |

- 速い振り子は動作停止後 約 0.5 秒で消える(物理は 約 2.5 秒)。余韻は遅い振り子で補う
- tiltstop: 握り位置とジンバルが近く、振り子はほぼ反応なし

## 揺れの較正(2026-10-03)
- PhysBone の角度制限は使えない(制限は瓶基準。瓶を傾けると振り子が真下を向けなくなり静止時の水平が崩れる)
- 骨の長さで振れ幅を較正: GimbalTip (0,-0.025,0)、Gimbal2Tip (0,-0.10,0)(周期はほぼ Pull で決まるので変わらない)
- シェーダー: `_SlowMaxDeg`(45°)遅い振り子の角度を頭打ち(余韻・揺れの強さ両方)/ `_ResidualMask`(20°)速い振り子が傾いている間は余韻を弱める(強制振動中に 3.7Hz の小刻みな揺れが乗るのを防ぐ。0° を横切る瞬間は余韻が埋めるのでチラつき対策にもなる)
- 変更前のシェーダーは `AlyxDebug/AlyxLiquid.shader.before_residual.txt` に保存

## 仕組み
- 基準面 = 平面 dot(p,N)=D。N はジンバル(振り子)由来、D は体積保存 LUT(x: 傾き角/π, y: 充填率)
- 液面 = 基準面 + 高さ場 η(どの項も平均ゼロ = 体積保存)。描画は視線レイマーチ(20 ステップ + 二分 6 回)、法線は η の 3D 勾配
  - 一次スロッシュモード: 円筒の固有形 J1(1.841 r/R) に合わせた差分 0.5819 s − 0.6702 s³ + 0.0954 s⁵(_SloshCurve=1 が物理値)
  - 非線形: _SloshPeak·(s²−0.25)(波頭が尖る, 既定 0.25)
  - 高次モード(_HighModes 0.6): 鞍型 (2,1) J2(3.054ρ)cos2θ と中央が上下する (0,1) J0(3.832ρ)。ベッセル関数は多項式近似。
    各モードの固有周波数 ω=√(g·j/R) で振動、振幅は揺れの強さに比例
  - 表面波: 高さを持つ sin 波 3 本(方向・波長を散らす)。角周波数は表面張力込みの分散式 ω=√(gk+(σ/ρ)k³)
    (_WaveHeight 0.4mm, _WaveLength 3.5cm。0.6mm/2cm だと横倒しの瓶で液面が沸騰したように見えて過剰だった)
  - 壁リング波(_RingHeight 0.25mm, _RingLength 1.2cm): 壁から内側へ減衰しながら広がる
  - 細波(法線のみ): 黄金角で方向を散らした 5 本(波長 約1cm〜0.35cm)+ 壁際のさざ波
- _MaxTilt(既定 50°)で水平からの傾きを制限
- ジンバルモード(`_GIMBAL_ON`): SkinnedMeshRenderer、rootBone=瓶本体。2 ボーン(各 0.5 ウェイト)
  - 特殊バインドポーズで「法線 = 速い振り子 Gimbal の向き」「タンジェント = 遅い振り子 Gimbal2 の向き」を分離して運ぶ
    (PA: 法線(0,-1,0) を通しタンジェントを消す / PB: タンジェント(1,0,0)→(0,-1,0)、法線を消す)
  - メッシュ側の約束: uv1=静止位置, uv2=壁法線, normal=(0,-1,0), tangent=(1,0,0,1)。スキニング後の位置は使わない(bounds 固定、updateWhenOffscreen=false)
  - 余韻: Gimbal2 の水平成分(_SlowMaxDeg で頭打ち)× _ResidualAmp(0.45)× (1 − 速い振り子の傾き/_ResidualMask) × cos(2π·_ResidualFreq(3.7Hz)·t) を液面法線に加算
  - 揺れの強さ(planeEps): max(速い振り子の傾き, 遅い振り子の傾き×0.5, 2 本のずれ×0.5)。遅い側とずれは _SlowMaxDeg で頭打ち。波と泡は √ で圧縮して使う
  - Skin Weights が 1 ボーンの環境ではタンジェントが 0 になり余韻だけ無効化(破綻しない)
- 泡・白濁(E = √(振れ角 / _FoamDevRef(25°)))
  - 白濁: 液面からの深さで減衰(exp(−depth/_FoamDepth))。色は白と液体色の混合(_FoamTint)× 環境光
  - 液面の泡: 壁際の細い輪と波頭に、格子ごとの小さな粒(Dots2)として並べる。座標は液面に沿った基底(横倒しで引き伸ばされない)
  - 気泡: 現在無効(_BubbleAmount=0)
  - 設定: ウォッカ FoamAmount 0.6 / Depth 4cm、赤ワイン FoamAmount 0.45 / Depth 2.5cm、_FoamEdge 0.5
- 液体の色: _LiquidColor(背景に掛ける色)+ _Opacity(0=透明ウォッカ, 0.8=赤ワイン)
- _MeniscusGlow: 液面と壁の接線を光らせて液面を見やすくする
- 同期: 液面・泡はすべて Transform 由来で追加パラメータなし。メニューのトグル 2 つ分のみ

## 既知の問題
- 揺れが一方向だけのとき、振り子が 0° を横切る瞬間に波・泡・白濁が弱まってチラつく。√ 圧縮と _ResidualMask で緩和、VR 実機で再確認待ち
  - 2 関節の振り子 → 振り子自体が暴れて不可。周期の違う 3 本目の振り子 → 同時に 0 付近になる瞬間が残り不可
  - 残る場合の案: PhysBone の Angle パラメータを Animator で平滑化(各クライアントで計算、同期なし)してマテリアルの「揺れの強さ」に渡す
- 止めた後の揺れの残り方が物理より短め(flick 後 約 1 秒、目標 約 2.5 秒)

## PhysBone 検証結果
- Simplified は Pull=0 だと重力が効かない。Pull>0 必須
- 揺れの周期は Pull でほぼ決まる(0.02→1.3Hz, 0.05→2.15Hz, 0.13→3.5Hz)。骨の長さは振れ幅に効く(短いほど大きく振れる)
- 減衰は Pull が大きいほど強い(spring 0.95〜1.0 はほぼ影響なし)。高い周期で長く揺らすことは不可 → 2 本目の振り子で余韻を作る
- 採用: Gimbal = Advanced, pull 0.13, spring 1.0, tip 0.025 / Gimbal2 = pull 0.02, spring 0.99, tip 0.10
- 角度制限(Limits)は瓶基準なので使えない
- Play 中のパラメータ変更は反映されない。変更はプレハブで行い Play し直す

## アップロード時の注意(修正済み)
- 瓶 FBX は Read/Write 有効・Blendshape Normals None・Blend Shapes 無効、液体メッシュ asset も Read/Write 有効にしないと VRChat 検証で失敗する

## 検証の手段
- `GimmickAI_1/AlyxDebug/`(プロジェクト外)にデバッグ画像を書き出し、Cowork から読み取り可(フォルダアクセス許可済み)
- 大量に書き出す前に C ドライブの空きを確認(満杯になったことがある)
- テスト用アバター上の瓶の確認は Play モードで行う(編集モードでは NDMF プレビューが元の描画を隠すため、デバッグカメラに瓶が映らないことがある)
  - Play 中に瓶を握った立ち姿勢で見るには、Hand.L 配下の VodkaBottle_L の rotation を identity にする
- デバッグ撮影時は ShaderUtil.allowAsyncCompilation=false にする(非同期コンパイル中は水色の仮表示や液面の欠けが出る。Play 直後も同様)
- Play 開始直後やスクリプト追加時はドメインリロードで MCP が 1 分ほど切断されることがある
- 編集モードで瓶を表示した直後に Unity が数分応答しなくなったことがある(シェーダーの準備か NDMF プレビューの再構築と推定)
- 書き換えは C# の File IO で行う場合 CRLF に注意(以前 CRLF 前提ミスでファイルを壊した)。正規化 + 一致数を確認する置換で行う
